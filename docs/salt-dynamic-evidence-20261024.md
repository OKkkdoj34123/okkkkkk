## 日志证据与修复范围

2026-10-24 20:01—20:03 的盐场调试日志记录了 15 个账号、30 次行军请求，
30 次均明确返回 200020。目标都是 12_23 或 14_24，来源均为 static-road。
14 个账号最后未找到目标，另 1 个账号进场查询超时。
入口响应给出 confId=57、legionWarMap=13、type=15；动态建筑数为 99。
原日志把 buildingData 截成深度限制，因此没有足够原始字段证明这两个坐标
在动态地图中缺失，还是存在但缺少归属字段；两者原先都会被标为 static-road。

确定的代码问题是：静态展示地图被当成可提交目标依据，且部分缺失归属被补为 -1。
另一个确定问题是：明确拒绝后 target 与 marching 状态残留，后续“未发送行军”
的表述掩盖了此前真实发生的请求。200020 的服务器内部具体含义仍未确认。

本补丁：

- 目标和经过的己方地块必须在动态数据中存在，且类型、归属均明确。
- 静态地图只供诊断，不推导中立归属，也不替动态数据补类型。
- 新增“选址中”“提交行军中”；仅收到接受响应后标记“行军中”，同步补齐页面状态标签。
- 明确拒绝后清除活动目标，保留坐标、错误码、时间及响应关联编号。
- 没有新目标时表述为“本轮未提交新行军/攻击”，并保留此前拒绝记录。
- 保留地图编号，以及六个邻格的原始 id/type/belongsLegionId、字段名、
  动态存在/删除状态、静态参考类型和排除标记，避免深度裁剪损失关键证据。
- 保持等待至少 120 秒、实际到达核验、攻击前重新核验和个人结算证据要求。
- 保留超时意图、防重复攻击、三次尝试上限及按战场/角色持久化记录。
- 不恢复已耗尽预算的 v2 失败记录，不清空浏览器存储。
- 保留取消自动周计划盐场的现状，仅沿用已有自建定时/手动入口。
- 不修改通用 BON/WebSocket、盐罐、日常错误码规则或推送布局。

## 应用与恢复

在项目根目录执行：

```powershell
python .\patch_salt_dynamic_evidence_20261024.py --check
python .\patch_salt_dynamic_evidence_20261024.py
pnpm build
```

补丁先检查全部目标文件及相关依赖的内容哈希，兼容 LF/CRLF 与 UTF-8 BOM。
任何代码冲突都会在写入前停止；已应用文件会跳过。项目管理 TXT 采用保留现有
内容的增量登记，因此不会因用户追加了其他模块日志而覆盖这些内容。
写入前备份原始字节与权限；正常写入异常自动回滚。不要同时编辑这些文件。
脚本不执行安装、联网、游戏请求、Git 提交、推送或部署。

恢复时使用脚本实际输出的备份目录：

```powershell
python .\patch_salt_dynamic_evidence_20261024.py --restore .\patch_backups\salt_dynamic_evidence_20261024_实际目录
```

恢复也会检查所有文件：若应用补丁后又修改了文件，将停止而不会覆盖修改。
新增文件仅在与补丁版本完全一致时删除。备份保留，恢复可以重复执行。
恢复脚本只恢复项目文件，不回退浏览器的执行记录。

## 问题和证据

当前日志的主要失败发生在本地选点阶段，尚未发送 war_startmarch，更没有到等待120秒或攻击阶段。不要通过增大120秒等待值处理这类错误。

现有 LegionWarMap.vue 使用 roadPointList 静态布局，再叠加 battlefield.buildingData 的实时类型和归属。HexGraph 同样先加载静态节点。
旧版自动任务直接在 buildingData 上找邻格，同时依赖每个动态条目都有 type 与 belongsLegionId。动态回包若没有列出普通道路，或省略静态 type，寻路会误认为无路可走。
例如项目真实大本营 7_4 的唯一地图邻格为普通道路 8_5。构造仅包含大本营的稀疏动态快照时，旧版报出与用户一致的“没有找到可达的非己方地块”；新版能选出8_5。
这证明源码缺陷可复现，但本次未取得用户当时的原始回包，不能声称已直接确认那15个账号的全部现场字段。

另一个问题：旧记录 state=failed、attempts=3 时，重新运行会直接显示缓存错误后退出，不再重新选点。日志中快速重复的3/3可能就是该路径，并不意味着本次又尝试了三遍。
legion_getbattlefield 请求超时属于入口读取问题，不等于地图错误，也不能仅凭修改选点保证连接稳定。

- src/utils/saltField/model.js：合并静态拓扑与动态归属；补充缺失的静态类型；六边形BFS最近目标；同距离优先普通道路；坐标数字字符串兼容；有界诊断；旧记录恢复资格检查。

- src/utils/saltField/runner.js：选点和抵达后的攻击前检查使用同一套合并地图；只恢复安全的旧版出发前失败记录；保留120秒下限、真实坐标检查、攻击意图记录与结算核验。
- src/utils/batch/tasksSaltOnce.js：仅增加恢复提示、目标来源及距离日志；保留最新的定时/手动共享控制器和返回结果结构。
- test/saltNavigation.test.js（新增）：17项针对本次问题的离线回归测试。

## 地图选择边界

复用项目自带324格地图，其包含20个大本营和225个普通道路格；不会生成任意坐标。
只有角色当前位置属于该已知地图且当前连接已经取得可识别的动态地图时，才补齐静态道路。
动态类型、归属优先；明确属于己方的道路不能作为攻击目标。大本营和核心不作为攻击目标。
没有实时归属的静态据点不会被假定为可攻击；普通道路可按现有静态布局作为候选，最终行军/攻击是否合法由服务器确认。
角色在其他地图布局时，只使用明确的实时地块。服务器显式删除的格子、无动态地图或坐标冲突均不盲目补点。
选择最近六边形距离；只有同距离时才优先道路。穿行只经过已知己方道路/普通据点，不穿越敌方大本营或核心。
若仍无目标，日志会包含当前位置、动态/合并格子数量和最多6个邻格的类型/归属，以便下一步定位；不输出Token或完整角色数据。

## 旧3/3记录如何恢复

不要求清空缓存，不更换 localStorage 键。
仅对未标记v2的旧失败记录执行一次恢复，条件全部满足：
1. 已确认布阵完成；本次重新连接同一战场同一角色，服务端返回idle与合法坐标。
2. 旧错误为精确的“没有找到可达的非己方地块；未发送行军/攻击”，或出发前legion_getbattlefield超时。
3. 没有目标、行军意图/时间/接受记录、攻击意图/接受记录、攻击前计数、完成证据或被拒绝目标列表。
恢复保留原3次失败及时间，开启本次修复版本最多3次尝试，保存版本标记，后续点击不会再次重置。
已行军、已攻击、结果不明、已完成或其他原因失败的记录不自动解锁。即使攻击被明确拒绝后清除了意图，保留的目标/攻击基线也会阻止迁移。
原有teamReady保留，因此已部署的单吕布不会因修复再部署一次。
如果入口仍超时，本版照常有界失败，不伪造进场成功。

## 安装

将 fix_salt_once_navigation_v2.py 放在项目根目录（或指定 --project 路径）：

```text
python fix_salt_once_navigation_v2.py --check
python fix_salt_once_navigation_v2.py
pnpm run build
```

部署Cloudflare后刷新网页，确保新包已加载；保持原浏览器与域名，不清除盐场记录。
本地测试可运行 pnpm run dev，入口仍为【批量日常 → 副本 → 盐场参与一次】，已有定时入口也保留。
安装只修改上述6个文件，不触发账号操作，不提交/推送Git。遇到版本冲突整体拒绝写入，不强制覆盖你的后续修改。
备份位于项目同级 <项目名>_salt_once_navigation_v2_backups/<时间_随机码>/。

恢复到本次修复之前（不删除原盐场功能）：
```text
python fix_salt_once_navigation_v2.py --restore
```

恢复不会清理浏览器防重记录。若安装后又修改了相关文件，恢复会拦截冲突。
可在安装前导出全部修改后的6个文件审查：
```text
python fix_salt_once_navigation_v2.py --extract salt_navigation_review
```
